## 1. ⚠️ 第一个发现：之前的 dump 是**残缺**的

```
sysfs 读 /sys/.../rom        -> 156,672 B   ← 内核 pci_get_rom_size() 截断了
NV_PROM 读 BAR0+0x300000     -> 960,349 B   ← 真身
```

验证：`NV_PROM[:156672] == sysfs dump` → **True**（sysfs dump 本身忠实，只是太短）
证据：NV_PROM 里 `PCIR` 出现在 `0x32CF3`，远超 156,672。

**完整 ROM 已取回并保存。所有后续分析都基于完整版。**

## 2. ★★ 核心发现：你的卡 = 零售 MSI 3080 + 1,516 字节

### 偏移对齐

```
A26R[i]  ≡  零售ROM[i + 0x9200]
```

九个标记**全部精确偏移 0x9200**：

| 标记 | A26R | 零售 MSI | 差 |
|---|---|---|---|
| `55AA7FEB` | `0x0` | `0x9200` | 0x9200 |
| `PCIR` | `0x170` | `0x9370` | 0x9200 |
| `PCIR` | `0xF49D` | `0x1869D` | 0x9200 |
| `NPDS` | `0xF4A5` | `0x186A5` | 0x9200 |
| `NPDS` | `0x26540` | `0x2F740` | 0x9200 |
| `PCIR` | `0x32CF3` | `0x3BEF3` | 0x9200 |
| `RFRD` | `0x33219` | `0x3C419` | 0x9200 |
| `NPDS` | `0xB7C20` | `0xC0E20` | 0x9200 |

（零售 ROM = `[0x9200 字节 NVGI 前导]` + `[正文]`；你的卡暴露的正是后半段正文）

**对齐验证**：shift `0x9200` → 相同 4KB 块 **215/235 (91.5%)**；其他 shift 全部 84~103。

### 对齐后的差异

```
A26R  vs  MSI2020   :  ██  1,516 字节 ██     ← 99.84% 相同！
A26R  vs  Asus2021  :    505,801 字节
A26R  vs  Elsa2021  :    505,836 字节
```

> **结论：你这张 A26R 20GB 卡的 VBIOS = 零售 MSI RTX 3080 10GB（2020-09-28 出厂固件）+ 一个仅 1,516 字节的 20GB 改装补丁。**

### 1,516 字节改装的内容（共 117 个区间）

| 位置（对齐后） | 内容 |
|---|---|
| `0x000034` | 日期串 `10/13/20` ← `09/28/20` |
| `0x0000C8` | 版本串 `7.00.14` ← `6.08.9A` |
| `0x000068` | 板名 `A26R RTX 3080 20GB` ← `PG132 SKU 30 VGA BIOS` |
| `0x0001A0` | 子系统 ID `DE 10 6D 14` ← `62 14 92 38` |
| `0x0B8E20` (443 B) | **指针表**：`1C 08 82 00 / 38 08 82 00 / 3C 08 82 00 …`（BAR0 寄存器地址 0x82081C…）← 零售版全零 |
| `0x083861` (128 B) | 内存训练图案 `10 10 10… / 32 32 32… / BA BA BA…` |
| `0x076B33` `0x076BA3` (72 B×2) | 内存时序表 `0C 5C 5C 5C…` |
| `0x007A6A` `0x007AF2` … (49 B×6, 每 0x88 一个) | `40 00 00 00 00 00 30 14` ← `50 …`（内存控制器配置）|
| `0x0824C2` (46 B) | `… AB 1A …` ← `… 00 14 …` |
| 其余 ~100 处 | 内存训练/时序/时钟表的零星值 |

**这 1,516 字节就是完整的 20GB 改装。** 位置精确可知。

## 3. ⛔ 2020 → 2021（ReBAR）是一次**固件大重建**，不是翻标志位

```
MSI2020 vs Asus2021 :  相同 4KB 块 = 99/234 (42.3%)
Asus2021 vs Elsa2021:  差异仅 2,671 字节（厂商噪声极小）
```

→ 57.7% 的块都变了。**说明 ReBAR 不是"改一个字节"，而是整个 DevInit/FwSec 换代。**

### 3.1 单字节候选（信号薄，不能定论）

用"Asus==Elsa（两家 2021 互相一致）来抵消厂商噪声"，找"只差一个字节、±64B 上下文完全相同"的位置：

```
aligned 0x083C74 (零售 0x08CE74):   MSI=FF  Asus=00  Elsa=00   A26R=FF
aligned 0x083D79 (零售 0x08CF79):   MSI=FF  Asus=00  Elsa=00   A26R=FF
```

稳健性曲线：`±4→147` `±8→43` `±16→13` `±32→3` `±64→2` `±128→2` `±256→1` `±512→0`

**判断**：这两个 `FF` 位于**大片全零区中的孤立字节**（局部熵 0.07）。形态上像"抑制标志"（GA100 的 DevInit suppress flag 就是 0x01/0x00），但**更可能是 2021 版把残留的 `FF` 填充清理成了 `00`**。**信号太薄，不足以据此刷固件。**

### 3.2 ⛔ 20GB 补丁**无法移植**到 ReBAR 版

```
20GB 补丁字节数 = 1,516
其中 MSI2020 与 Asus2021 在这些位置原本就不同 = 1,482 (97.8%)
可移植字节 = 0 / 2,731  (0.0%)
```

**在全部补丁位置上，两版固件本来就已经不同。** 强行移植生成的候选 ROM 与真实卡相差 504,531 字节。

→ **20GB 内存配置与固件版本深度耦合，无法靠 diff 拼出一份"20GB + ReBAR"ROM。**

| 路线 | 判定 |
|---|---|
| **A. 驱动/Booter 特权写寄存器** | ❌ 需要 SEC2 签名时间窗口漏洞，610.57.04 无此原语 |
| **B. 用户态直接写寄存器** | ❌ 语义不可控（实测 `0xffffffcf`→写`0xffffffdf`→读回`0xfffffece`），无法预测/还原 |
| **C. 靠 diff 自建 20GB+ReBAR ROM** | ❌ **本轮证伪**：两版固件差异过大，补丁可移植性 0% |
| **D. 刷一份现成的 20GB + ReBAR ROM** | ⬅️ **唯一剩下的路** |

## 5. 唯一剩下的路：找一份现成的 20GB ReBAR ROM

### 5.1 已有线索 ⭐

TechPowerUp 的显存筛选里 **`20480 MB` 只有 5 份**。其中若有 RTX 3080 20GB 且是 2021 年后的版本 → **直接就是刷写候选**。

页面：`https://www.techpowerup.com/vgabios/` → 筛 `Memory Size = 20480 MB`（再叠加 `Card Model = RTX 3080`）

（TPU 的下载被 Cloudflare 拖动式验证挡住，我这边无法自动抓取，必须浏览器手动下。）

### 5.2 问卖家

> 「A26R RTX 3080 20GB 这批卡，**有没有支持 Resizable BAR 的 VBIOS**？」

### 5.3 拿到之后的刷写准备（**必须按顺序**）

1. ⚠️ **先买 CH341A SPI 编程器 + SOP8 夹子**（砖机唯一救援手段）
2. 4 张原厂 ROM 已有备份 ✅
3. **先在 1 张卡上试**，成功再推广
4. 用 `nvflashk` / `OMVGflash` 刷（GeForce 签名锁 2023 年已被绕过）
5. 刷完 `lspci -vv -s <bdf> | grep -A3 "Physical Resizable BAR"` 看 supported 列表是否变大
6. 若变大 → 桥窗口会自动跟着涨（BIOS 的 `Re-Size BAR` 已是 Enabled）→ 触发 PCI rescan
7. 然后才轮到测 NCCL / llama.cpp

## 6. 必须保留的诚实结论

即使拿到 20GB ReBAR ROM 并刷成功：

- BAR1 变大 → aikitoria 补丁的 static BAR1 mapping 路径可达 → **这是打通 P2P 的必要条件**
- **但 NCCL 集合通信能否不挂死，仍未验证**（club-3090 记录过"满尺寸 32GB BAR1 也是必要非充分"）
- **而 llama.cpp 的最终收益仍未验证**（外部 4×3090 实测在 P2P 可用时 llama.cpp 收益≈噪声）

所以这是一条**必要条件链**，不是充分条件链。每打通一环，才解锁下一环的判断。

## 9. 最终裁定（2026-09-24）

**卖家确认：A26R RTX 3080 20GB 不存在支持 Resizable BAR 的 VBIOS。**

四条路线全部封闭：

| 路线 | 结论 | 依据 |
|---|---|---|
| **A. 驱动 / SEC2 Booter 特权写** | ❌ | 需要签名校验时间窗口漏洞；`kgspSec2PostblTiming*` 在 610.57.04 中不存在 |
| **B. 用户态直接写寄存器** | ❌ | 语义不可控：写 `0xffffffdf` → 读回 `0xfffffece`，无法预测/还原 |
| **C. 靠 diff 自建 20GB+ReBAR** | ❌ | 补丁可移植性：跨厂商 0%，同厂商 8.6%；2020→2021 是 38 万字节重写 |
| **D. 获取现成的 20GB+ReBAR 固件** | ❌ | **卖家确认不存在**；TPU 全站 20GB ROM 仅 5 份，无一是 3080 |

**追加排除：**

- 零售 3080 ROM 与 A26R 的关系已完全查清（`= MSI 2020 + 1,516 字节`）
- 曾怀疑的"DevInit 寄存器表槽位"（零售 `0x0C2020`）非零字节数 22/169/169/22，**与是否 ReBAR 不相关**，排除
- GA102 工作站版（A4500，2021-10-12）为 2MB 容器，与本品结构仅 35.5% 相符，无法作为参照

> **根因：公开领域不存在"GA10x 的 BAR1 尺寸字段位置"这一信息。**
> 这不是分析能力问题，是信息不存在。

### 由此得出的**确定性结论**

既然 P2P 已被证明在本硬件上无法实现，那么：

> **PEX88096 交换卡已经没有任何剩余价值，只剩成本 —— 它把 4 张卡的主机中转带宽压缩成 1 条共享 x16。**

实测：4 卡并发聚合 H2D 仅 **26.2 GB/s**（≈ 单卡的 1.07 倍）；若 4 卡直插、各占一条独立 x16，理论上是 **~98 GB/s**。

**结论：拆掉交换机是正确的，且这是用户最初的判断。**

## 8. 补充验证：MSI 自家 2021 ReBAR 版 —— **同样不可移植**

新增样本：

| 文件 | 大小 | 版本 | 日期 | ReBAR |
|---|---|---|---|---|
| `MSI.RTX3080.10240.200928.rom` | 999,424 B | `94.02.26.08.9A` | 2020-09-28 | ❌ 非 ReBAR |
| `MSI.RTX3080.10240.210308_1.rom` | 999,424 B | **`94.02.42.00.2C`** | 2021-03-08 | ✅ ReBAR 时代 |

### 假设与结果

**假设**：换回**同厂商**的 2021 版，内存训练表（板级相关）可能被保留 → 1,516 字节补丁可移植。

**结果：证伪。**

```
MSI2020 vs MSI2021 : 相同 4KB 块 124/234 (53.0%)   逐字节差异 379,981
                     (对比跨厂商 MSI2020 vs Asus2021: 42.3% / 505,801)

20GB 补丁可移植性:
  可直接套用 (MSI2020 == MSI2021) = 130 / 1,516 ( 8.6%)
  会覆盖新版数据                 = 1,386 / 1,516 (91.4%)
```

关键区域逐块（对齐后的内存训练表区）：

| 对齐偏移 | 零售偏移 | 两版差异 | 该区补丁字节 |
|---|---|---|---|
| `0x076000` | `0x07F200` | 3,291 B | 326 |
| `0x077000` | `0x080200` | 3,447 B | 171 |
| `0x078000` | `0x081200` | 3,186 B | 49 |
| `0x07B000` | `0x084200` | 2,086 B | 0 |
| `0x07F000` | `0x088200` | 1,929 B | 0 |

→ **每个 4KB 块差异 1,900~3,900 字节，内存训练表被整段重写。**

### 最终结论

> **无法通过 diff 拼出 "RTX 3080 20GB + ReBAR" 固件。**
> **20GB 内存配置与固件版本深度绑定，跨代之间该区域被完全重写，补丁不可移植。**

这不是努力不够，而是**公开渠道缺少必要的原料**：一份"20GB + ReBAR"的成品固件。
