# 88096 交换卡对「无 P2P 中转」的性能影响 — 实测报告

**日期**: 2026-09-23
**主机**: `ai3080` — 4× RTX 3080 20GB + Broadcom PEX88096 交换卡
**驱动**: 610.57.04 (aikitoria `610.57.04-p2p-v3` 魔改模块)
**结论**: 用户判断成立 —— **在 P2P 走不通的前提下，88096 反而拖慢了共享内存中转方案**

---

## 一、链路结构（实测）

CPU 到交换机的路径：

```
CPU 根端口 c0:03.1  ←→  交换机上行口 c4:00.0
    Gen4 x16 (16GT/s, Width x16)         ← 只有这一条上行
交换机下行口 c5:00.0 / c6:00.0 / c7:10.0
    Gen4 x16
4 张卡端点 (c8/cb/cf/d0)
    max Gen4 x16，空闲降至 2.5GT/s
NUMA: 单节点 (node 0)，4 卡同域
```

**关键：4 张卡共享一条 Gen4 x16 上行链路（理论 ~31.5 GB/s）。**

---

## 二、带宽实测

### 单卡（pinned 内存）

| GPU | H2D (GB/s) | D2H (GB/s) |
|---|---|---|
| 0 | 24.55 | 24.50 |
| 1 | 24.80 | 24.51 |
| 2 | 24.74 | 24.49 |
| 3 | 24.96 | 24.54 |

单卡跑满自己的 x16，~24.5 GB/s，符合 Gen4 x16 实际水平。

### 4 卡并发（pinned）— 关键数据

| 指标 | 实测 | 若无瓶颈应为 |
|---|---|---|
| 聚合 H2D | **26.23 GB/s** (每卡 6.56) | ~98 GB/s (4×24.5) |
| 聚合 D2H | **12.14 GB/s** (每卡 3.03) | ~98 GB/s |

**聚合只有单卡的约 1.07 倍，完全没能 4 倍扩展 → 共享上行 x16 是硬瓶颈。**

### 跨卡中转（无 P2P 时 NCCL 的实际路径）

```
GPU i → pinned host → GPU j
```

| 方向 | GB/s | 延迟 (32MB) |
|---|---|---|
| 全部 12 个有向对 | **12.55 均值** | 2659 µs |
| 最好 (GPU0→GPU2/3) | 12.63 | 2657 µs |
| 最差 (GPU0→GPU1) | 11.74 | 2858 µs |

单对中转 ~12.6 GB/s（约为单卡单向带宽的一半，因为要过两次 PCIe：下行 + 上行）。

## 三、结论：用户判断成立

### 用 88096 的情况（当前）

- 4 卡流量**汇聚到交换机 → 单条 x16 上行**
- 聚合 H2D 26 GB/s、D2H 12 GB/s
- 4 卡并发跑中转时，每卡只剩 3~6.6 GB/s

### 不用 88096 的情况（假设 4 槽各自独享 x16）

- 4 条**相互独立**的 x16 通道
- 聚合可达 ~4 × 24.5 ≈ **98 GB/s**
- 每卡并发时仍能接近满速

**差值约 3.7 倍（26 vs 98 GB/s）。** 你的分析是对的。

### 为什么 88096 在这里帮不上忙

88096 的价值本来在于让 GPU 间拓扑变成 `PXB`/`PIX`（走交换机而非 CPU 宿主桥），
从而**为真 P2P 提供物理条件**。实测拓扑确实变成了 `PXB`/`PIX`：

```
        GPU0    GPU1    GPU2    GPU3
GPU0     X      PXB     PXB     PXB
GPU1    PXB      X      PXB     PXB
GPU2    PXB     PXB      X      PIX
GPU3    PXB     PIX     PXB      X
```

**但 P2P 最终被 BAR1=256MB 卡死**（详见 `p2p-conclusion-ai3080.md`）。
于是数据只能走内存中转，而中转恰恰是 88096 **最不利**的场景 —— 它把 4 条独立通道
合并成了 1 条共享上行。

## 四、顺带修正我之前的一个说法

我之前说「NCCL 走共享内存经过 88096 比走 CPU 内存快」——**这是错的**，
用户的纠正是对的：

- 经过交换机 = 所有流量挤一条 x16 上行 → **更慢**
- 不经交换机 = 4 条独立 x16 并行 → **更快**

原因是我把「P2P 可用时交换机的价值」错误地套用到了「无 P2P 的中转场景」。

---

## 五、实测数据对决策的意义

### 与真 P2P 的差距

| 路径 | 带宽 | 备注 |
|---|---|---|
| 真 P2P（大 BAR1 卡） | ~20-25 GB/s 直连 | 不经主机内存 |
| 内存中转（当前，过 88096） | 12.55 GB/s | 过两次 PCIe |
| 内存中转（无 88096） | 单对相近，**聚合高得多** | 4 卡并发不互相抢 |

单对带宽差距不算悬殊（12.6 vs ~22），但**延迟和并发扩展性差距大**：
真 P2P 延迟约 1-2 µs，中转约 2659 µs/32MB。

### 对工作负载的影响

| 并行方式 | GPU 间流量 | 无 P2P 时表现 |
|---|---|---|
| 数据并行 / 多实例（各卡独立） | 无 | ✅ **完全不受影响，推荐** |
| 流水线并行 (PP) | ~7 MB/s，极小 | ✅ 影响很小 |
| 张量并行 (TP) | 每层 all-reduce，对延迟极敏感 | ❌ **严重变慢** |

因为张量并行吃的是**延迟**而非带宽，中转路径的 2659 µs 级延迟会让 TP 基本不可用。

---

## 六、建议

1. **张量并行不要指望**。无论有没有 88096，无 P2P 时 TP 都会被延迟拖垮。
   4 卡的正确用法是**数据并行 / 多实例推理**。

2. **如果主要跑数据并行**，88096 留着无害（各卡独立时用不到卡间通信）。

3. **如果确实要大量卡间通信**（TP），考虑：
   - 把 4 卡从 88096 上取下，插主板 4 个独立 x16 槽 → 中转聚合带宽可提升约 3.7 倍
   - 或换 BAR1 能覆盖显存的卡（3090/4090/专业卡）跑真 P2P（~20-25 GB/s 且低延迟）

4. **注意前提**：不用 88096 的收益，取决于主板是否真能提供 4 条独立 x16
   （需要 CPU 提供 64 条 Gen4 通道）。若主板实际是共享或降宽，收益会打折。
